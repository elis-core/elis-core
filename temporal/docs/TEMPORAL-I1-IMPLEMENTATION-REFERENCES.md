### Material correction made this pass: decomposition boundary Workflow integration

**Adjudication:** classified as a **material T2 gap**, not an acceptable T3 deferral — the required T2 architecture (Workflow → Hermes/LLM Activity → structured proposal → recorded Activity result → deterministic Workflow validation → only authorized child work proceeds) was demonstrated nowhere in the codebase, and a standalone validator with unit tests does not, by itself, prove the boundary is Workflow-reachable.

**Correction:** added `src/elis_temporal/workflows/decomposition_workflow.py` — a minimal `DecompositionWorkflow` that calls the existing `run_agent_activity` to propose a decomposition, then calls `validate_decomposition_proposal` deterministically in Workflow code against the recorded Activity result, returning only children from an AUTHORIZE verdict. Registered on `build_worker_for_profile` alongside the other T2 workflows. Deliberately does NOT spawn child Workflows for authorized children — that is representative T3 Core/Research orchestration scope, out of this bounded correction. 3 new integration tests added (`tests/integration/test_decomposition_workflow.py`) proving: (1) a valid proposal is AUTHORIZEd and its children returned, (2) a policy-violating proposal (privilege escalation) is REJECTed with zero authorized children, (3) non-structured/free-prose Activity output lands in its own `invalid_proposal_result` stage, never coerced into either verdict.
